# skill eval 迭代

你负责实验设计。先定成功标准，再跑盲评，最后合成。不要用自我感觉代替对照。

本技能继承上游 poteto-mode `playbooks/eval.md` 的盲评纪律，并加上 skill 推广特化：无 skill 对照、子代理隔离、门禁硬度推广标准。

## 何时用

- 刚改完一个 skill，想知道有没有变好
- 要把 skill 从领域专版收成通用版
- 需要证明「有 skill」比「无 skill」更适合作门禁

## 盲评非协商（继承上游）

候选看得到的路径、文件名、提示里，禁止出现：
`eval` / `test` / `judge` / `experiment` / `rubric` / `score` / `compare` / `benchmark` / `candidate` / `arena`

另：

- 候选提示必须像真人用户请求。只说目标，不说在测什么
- 不诱导候选自报用了哪些 skill / 原则 / 文件。chain 从真实打开的文件与产出形状判定
- 目录与 slug 用项目形名字
- 不告诉候选还有其它变体
- 裁判可以知道自己在打分，但只看脱敏标签，不看模型名或变体真名
- 两个变体以上：同一裁判、同一量规、一次打完

## 子代理（强制）

- 每个候选一个独立子代理。只给该目录、有机提示、交卷路径
- 裁判另开子代理。只给脱敏交卷 + 量规 + 埋点事实
- 父会话只合成，不冒充候选写审查
- 无 skill 对照也是子代理。提示与目录都不得出现 playbook / skill
- 若环境支持多模型：候选走不同模型；裁判走不同模型族（对齐 arena）。不支持则同模型也可跑，但不得因此省略盲评与无 skill 对照

## 步骤

### 1. 定框架（只给裁判）

写清在测的变体、成功行为、量规 3–8 条（每条 0–2）。量规对候选保密。
量规至少覆盖：阻塞裁决、姐妹路径召回、假声明、假绿测试/CI、合同破裂 framing、门禁是否可被「改文档 / out of scope」绕过。

### 2. 搭脱敏环境

每候选独立目录。放入同一 fixture。有 skill 变体放入 playbook；无 skill 对照不放。

### 3. 写有机提示

有 skill：要求按目录内 playbook 交卷。
无 skill：只要求开 PR 前仔细审查，给出意图、问题、是否允许开 PR。

### 4. 并行开跑候选

至少包含无 skill 对照。产出写入各自交卷文件。

### 5. 盲审裁判

交卷复制到 alpha / bravo 等标签目录。裁判输出打分表、总分、推荐底座、分歧、以及「单独拿来当合并门禁是否安全」。

### 6. 验 chain（能做就做）

读各候选 transcript（仅当前工作区）。看真实打开过哪些文件。不要跨项目乱搜。没有 transcript 时，用交卷是否点名埋点文件/符号作为弱替代，并在合成里标明证据等级。

### 7. 父会话通读并合成

对照裁判。分歧则重审量规或交卷。交卷给用户：变体、量规与分数、要点、裁判结论、合成、推广决定。

## 推广标准

目标变体在关键量规上不低于对照。跨领域 fixture（若有）不掉点。
无 skill 也能 BLOCK 时，仍以门禁硬度为准：修法是否结构优先、是否点名唯一分叉变体、是否能被「改文档 / intentional split / CI deferred」绕过。能被绕过则不得推广为「可作唯一合并门禁」。

## 完成标准

- 至少两个变体（含无 skill），各由独立子代理产出
- 独立裁判盲评落盘
- 有明确推广 / 不推广决定与理由
